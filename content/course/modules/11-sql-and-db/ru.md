# SQL и базы данных для QA

SQL — практический навык QA, потому что многие действия продукта сохраняются как данные. Кнопка может показать неверный баланс, отчёт может пропустить запись, API может вернуть подозрительное значение. SQL помогает посмотреть исходные данные и объяснить находку.

В этом модуле акцент на безопасном чтении: понимать таблицы, писать `SELECT`-запросы и превращать результат в QA-наблюдение.

## Базы данных в продуктовой работе

База данных — организованное место для хранения и получения данных. Во многих веб- и мобильных продуктах приложение читает и записывает данные через базу.

Реляционная база хранит данные в таблицах:

- таблица содержит строки и столбцы;
- строка — одна запись, например пользователь, счёт, заказ или транзакция;
- столбец — один атрибут, например `email`, `status`, `amount` или `created_at`;
- таблицы связываются через идентификаторы: `account_id`, `user_id` и похожие поля.

Распространённые реляционные СУБД: PostgreSQL, MySQL, Microsoft SQL Server, MariaDB и SQLite.

## Зачем QA нужен SQL

SQL помогает тестировщику:

- подтвердить, что действие пользователя изменило нужные записи;
- сравнить данные в UI, API и базе;
- найти пропущенные, дублирующиеся или противоречивые записи;
- подготовить точечные тестовые данные;
- разобраться, видимая проблема связана с данными, бизнес-логикой или отображением.

Сильная работа с SQL — это не только получить строки. Важно задать точный вопрос и объяснить, почему результат имеет значение.

## Базовая форма `SELECT`

Большинство QA-проверок базы начинаются с `SELECT`:

```sql
SELECT column_name, another_column
FROM table_name
WHERE condition;
```

- `SELECT` задаёт нужные столбцы.
- `FROM` задаёт таблицу.
- `WHERE` фильтрует строки.

Примеры:

```sql
SELECT *
FROM users;
```

```sql
SELECT name, email
FROM users
WHERE status = 'active';
```

```sql
SELECT account_id, balance
FROM accounts
WHERE balance < 0;
```

Для QA-доказательств конкретные столбцы обычно понятнее, чем `SELECT *`: результат проще читать и передавать команде.

## Фильтрация и сочетание условий

Частые операторы:

- `=` равно
- `!=` или `<>` не равно
- `>`, `<`, `>=`, `<=` сравнение чисел или дат
- `LIKE` поиск по шаблону
- `IN` совпадение с любым значением из списка
- `IS NULL` значение отсутствует
- `IS NOT NULL` значение есть
- `AND` оба условия истинны
- `OR` истинно хотя бы одно условие

Примеры:

```sql
SELECT order_id, status
FROM orders
WHERE status IN ('Pending', 'Processing');
```

```sql
SELECT user_id, email
FROM users
WHERE email LIKE '%@example.com';
```

```sql
SELECT card_id, account_id
FROM cards
WHERE expires_on < '2026-09-25'
  AND status = 'active';
```

## Сортировка, ограничения и групповые проверки

`ORDER BY` делает просмотр результата предсказуемым:

```sql
SELECT account_id, created_at, amount
FROM transactions
ORDER BY account_id ASC, created_at DESC;
```

`LIMIT` ограничивает объём вывода при исследовании:

```sql
SELECT *
FROM transactions
ORDER BY created_at DESC
LIMIT 10;
```

`GROUP BY` помогает отвечать на вопросы про количество и сводки:

```sql
SELECT status, COUNT(*) AS transaction_count
FROM transactions
GROUP BY status;
```

Агрегатные функции: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.

## Объединение таблиц

QA-вопросы часто требуют данные из нескольких таблиц. `JOIN` соединяет строки по связанным столбцам.

```sql
SELECT accounts.account_id, accounts.owner_name, cards.card_id, cards.status
FROM accounts
JOIN cards
  ON cards.account_id = accounts.account_id;
```

Полезные варианты:

- `INNER JOIN` возвращает строки, где есть совпадение в обеих таблицах.
- `LEFT JOIN` сохраняет все строки из левой таблицы и ставит `NULL` справа, если совпадения нет.
- `LEFT JOIN ... WHERE right_table.id IS NULL` удобно для поиска отсутствующих связанных записей.

Пример: транзакции без записи счёта.

```sql
SELECT transactions.transaction_id, transactions.account_id
FROM transactions
LEFT JOIN accounts
  ON accounts.account_id = transactions.account_id
WHERE accounts.account_id IS NULL;
```

## Подзапросы

Подзапрос — запрос внутри другого запроса. Он позволяет сделать условие зависимым от другого результата.

```sql
SELECT transaction_id, account_id, amount
FROM transactions
WHERE account_id IN (
  SELECT account_id
  FROM accounts
  WHERE status = 'closed'
);
```

Вопрос здесь такой: какие транзакции относятся к закрытым счетам?

## Безопасные привычки QA в SQL

- Для исследования выбирайте запросы только на чтение.
- С `UPDATE`, `DELETE` и `INSERT` работайте только в контролируемой среде и по командному процессу.
- Сначала фильтруйте. Пропущенный `WHERE` может затронуть все строки.
- Сохраняйте вопрос, запрос и результат вместе, чтобы другой человек понял доказательство.
- Если результат удивляет, проверьте, допускает ли модель данных такой случай, прежде чем называть его дефектом.
